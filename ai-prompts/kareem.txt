**`validation-exception.factory.ts`:** the `exceptionFactory` for the global `ValidationPipe`. It turns class-validator's `ValidationError[]` into

- One `details` entry per field: `{ field, message }`.

**`error-body.ts`:** a pure function `toErrorBody(exception: unknown, path: string, now = new Date())` that returns `{ statusCode, body }`. The body has the shape above, with `details` only when present. The rules, in order:

| Exception | Status | Code | Message | Details |
|---|---|---|---|---|
| `HttpException` whose response object has a string `code` | `getStatus()` | that code | its `message` | its `details`, if an array |
| other `HttpException` | `getStatus()` | by status: 400 `VALIDATION_FAILED`, 401 `NOT_AUTHENTICATED`, 403 `FORBIDDEN_ROLE`, 404 `NOT_FOUND`, 409 `CONFLICT`, any other 4xx `REQUEST_FAILED`, 5xx `INTERNAL_ERROR` | the response's `message` (an array joined with `; `), else `exception.message` | none |
| object with `code === 11000` (Mongo duplicate key) | 409 | `CONFLICT` | `Duplicate value` | one per key of `keyValue`: `{ field, message: 'already exists' }` (omit if no `keyValue`) |
| Mongoose `Error.ValidationError` | 400 | `VALIDATION_FAILED` | `Validation failed` | one per key of `errors`: `{ field: key, message: errors[key].message }` |
| Mongoose `Error.CastError` | 400 | `VALIDATION_FAILED` | `Invalid value` | `[{ field: path, message: 'invalid value' }]` |
| anything else | 500 | `INTERNAL_ERROR` | `Internal server error` | none |

`timestamp` is `now.toISOString()`. `path` is the argument.

## Context you need

**Allowed calls** (`docs/database/data-model.md` §6.1): payments calls nobody (it uses the port). flights and hotels call reference-data and storage. accounts and fx call reference-data. itineraries calls reference-data, fx and storage. blog calls storage. admin calls audit. flight-bookings and hotel-bookings call payments.

**Payments rules** (`docs/ai/skills/travel-platform/references/bookings-payments.md` §4, §6, §7):
- Payments never writes a booking, and bookings never call Stripe.
- `POST /api/payments` checks the booking through the port: it belongs to the user, is `pending_payment`, and `holdExpiresAt > now`.
- On cancellation, the booking module calls `PaymentsService.refund(...)` after its commit, and only if the refund amount is > 0.
- One refund per booking: `refunds` has a unique index on `{ bookingType, bookingId }`.
- Reasons: `user_cancellation`, `provider_cancellation`, `late_payment` (a full refund).
- The Stripe PaymentIntent uses idempotency key `pi-<type>-<bookingId>`; the refund uses `refund-<refundId>`.

**Uploads** (GEN-08, `references/backend.md` §11):
- JPG or PNG only, at most 5 MB each, random file names, stored on the server and served at `/uploads/<key>`.
- Documents store `ImageRef { _id, key }`; the URL is computed, never stored.
- Feature services enforce the counts (≤ 5 per post, activity or hotel; 1 airline logo).

**FX** (`references/domain-rules.md` §2):
- `convert` uses the newest rates document: `amount × rates[to] / rates[from]`, adjusted for each currency's `minorUnits` (JPY has 0), rounded half up.
- An unknown currency gives `400 UNSUPPORTED_CURRENCY`; no rates at all gives `503 RATES_UNAVAILABLE`.
- Responses carry `{ displayCurrency, rateDate }`.

**Reference data:**
- Dataset IDs are string `_id`s: airport `'CAI'`, city `'cairo'`, country `'EG'`, currency `'USD'`, attraction `'att-1'`.
